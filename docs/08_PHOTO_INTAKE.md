# Intake des photos

`intake/` est une zone de travail, pas le catalogue publié. Le workflow futur sera semi-automatique :

1. déposer les originaux dans `intake/photos/` ;
2. préserver fichiers, métadonnées et empreintes sans écrasement ;
3. regrouper les vues susceptibles de montrer le même objet ou lot ;
4. retranscrire les marquages visibles ;
5. retranscrire séparément les quantités manuscrites ;
6. proposer une identification et ses alternatives ;
7. rechercher et enregistrer les sources documentaires ;
8. créer un brouillon sans publier ;
9. faire valider identité, quantité, droits et destination par une personne ;
10. publier données, médias et annexes ;
11. classer logiquement l'entrée dans `processed/` ou `rejected/`, sans altérer l'original.

## Cas à traiter

Une photo peut contenir un seul objet, plusieurs identiques ou plusieurs différents. Plusieurs photos peuvent être recto/verso, détails ou objets distincts : le regroupement reste une hypothèse jusqu'à validation. Une quantité écrite à côté est une annotation, pas automatiquement un comptage ; si elle est ambiguë, le stock reste inconnu. Un lot visible ne garantit pas que tous les exemplaires sont identiques.

Marquage illisible, référence partielle, absence de marquage et module générique vendu sous plusieurs noms conduisent à une proposition prudente, plusieurs candidats ou « non identifié ». L'outil ne doit jamais compléter un texte illisible par vraisemblance sans marquer la déduction.

La validation humaine est obligatoire pour les identifications ambiguës et avant toute affirmation que la photo montre un article précis. Le classement `rejected/` signifie inutilisable pour la publication, pas suppression.
